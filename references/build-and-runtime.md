# 开发与运行兼容

## 产品与升级

先从源代码、当前 APK、已发布基线和用户最终要求确定流程。新应用先完成首次进入、核心操作、保存恢复、返回、错误反馈及权限设置，交付可操作体验而非静态展示。按主题设计真实页面，截图检查触控、布局、深浅底系统栏、键盘和底部安全区。

只有二进制时先寻找匹配工程和构建记录；不能把改后缀或版本字符串称作功能同步。保留包名、发布签名与数据迁移；密码通过安全本地机制读取，不入 Git。versionCode 应高于安装/商店基线，versionName 按产品策略，不强制每次材料修改都升级。

核对最终 APK 的 application/launcher label、语言资源、自适应/普通图标、minSdk/targetSdk、ABI、组件导出、SDK 和权限。targetSdk 依当前商店要求，不固定 33/34，不靠降低 target 绕规则。高 API 调用按版本防护，必要时隔离到独立类；确认依赖/desugaring 最低支持范围。

使用 apksigner 和 manifest/badging 工具留证。升级检查既有课表、照片、闹钟和设置保留，不卸载重装掩盖迁移问题。

## 启动失败定位

1. 收集实际版本、审核机型/OS、首次/再次启动和附件。区分崩溃、白屏、资源失败、JS 语法、桥接错误，读 logcat/控制台/资源请求。
2. 桌面新 Chrome 可运行不代表旧 Android WebView 可运行；构建目标覆盖实际审核内核。
3. 按需转译语法、polyfill、特性探测和传统 IIFE bundle。IIFE 不自动消除新语法/API；不一律禁用 MessageChannel。
4. 离线资源随包，核对路径大小写、MIME、CSP、资源拦截、字体/图标和启动脚本。首屏不能因非必要 CDN 失败而瘫痪。
5. 优先 WebViewAssetLoader HTTPS 本地域；限制桥接来源和暴露接口。不为修资源随意打开通用 file URL 跨域访问。INTERNET 按实际网络需求声明，不宣称纯本地应用缺权限必然崩溃。
6. 原生 WebView 初始化、loadUrl 前、JS 启动和桥接就绪分段留证。失败保留可读页面/重试，不立即 finish 伪装成闪退。
7. 修复根因后按授权做针对性验证，缺旧设备/云测时明确，不保证一次过审。

## 状态与交互

- 重复日期空数组是有效“不重复”，用 null/undefined/schema 区分缺省。不能用数组长度将空数组还原为每天；保存、重启和升级语义一致。
- 返回先关弹层、再回上一页，根页才处理退出。
- 长按结束应有进度、取消和成功反馈，真正停止会话；处理遮挡、pointercancel 和 click 双触发。
- 状态栏浅底配深色图标；导航条与背景统一，检查 edge-to-edge/insets。
- 权限拒绝、相机取消、桥接超时恢复按钮和忙碌态，不用永久 loading 掩盖问题。
