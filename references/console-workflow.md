# 后台执行、上传与保存

## 操作前

确认用户授权的商店、应用、平台和动作。核对 appId、projectId、包名和品牌，使用当前页面真实链接；缺项目路径/旧路由可能空白，不把空白误判成无应用。登录过期由用户完成扫码，不取 Cookie/密码。工具有浏览器 DOM/API 时优先；CDP/脚本仅在已有明确授权和当前环境允许时使用，不复用硬编码端点或他人会话。

## 上传与资料

1. 读审核报告、当前分类、已选包、现有政策和素材，列此次确需改变的字段。
2. 若只是分类/描述问题，编辑字段并保存，不无故造新版本或重复上传原包。
3. 需新包则确认最终中文文件名、manifest、版本、签名、哈希和具体修复。工具不支持中文路径时修 Unicode 路径/文件元数据；不能用 ASCII staging 让远端最终显示 kejian、keshi 等工程名。若无法保障中文远端名先停该次上传并说明技术限制。
4. 等待文件/包解析与表格异步数据，检查明确版本和合法性，不能看到按钮就认为列表加载完成。超时/解析弹窗后先查软件包管理，服务器可能仍处理；避免重传制造重复。
5. 多个同版本行时选文件名正确、已达标且 radio 可用的行，不盲选第一行。原包/重复项不随意删除。
6. 对照最终包修改介绍、真实权限/隐私标签、更新日志、审核备注、截图与图标；不照搬另一平台。

## 自检与停止点

当次用户明确不要测试时，跳过平台自检，不沿用早先“启动自检”的偏好继续创建任务。关闭尚在配置的流程，准确区分测试库存上传与任务启动；交付标明未测试。用户只取消测试不等于取消已授权的资料修改和草稿保存。

### 项目关联门槛

测试入口要求“关联项目”时，先从后台实际项目名称、唯一标识、项目详情和现有应用归属交叉确认目标 App、Android 平台及包名。URL 的 projectId 可能沿用其它应用，同名项目也不足以证明身份；不能凭 URL、同名或邻近列表项直接绑定。

优先选择已存在且身份核实一致的项目，不因测试入口要求就自动新建。若项目归属不清、存在多个候选，或绑定/迁移可能改变已开通服务、数据或其它应用关联，应先向用户说明具体影响并确认，不能以“继续自检”的授权推定同意服务迁移。

核实并关联后重新检查应用与项目归属，再进入测试。打开测试入口、完成关联、创建任务和任务实际排队/执行是四个不同状态；只有读取到测试任务 ID、目标包/设备配置及排队或运行状态才可报告“已启动”。涉及新增收费、购买配额或另行接受协议时停在相应确认点，原有上传/自检授权不自动覆盖。

依用户要求启动平台启动/兼容等自检，读取排队/进行中/完成结果和附件。失败按证据定位，不能仅凭哈希/合法性达标报告“自检通过”。若当前控制台无可用入口、无配额/设备或自检需额外授权收费，记录真实阻碍，不假装已启动。

保存后等待成功响应，再重新进入核对版本、包、分类、隐私关联和图片。保存失败先读字段错误，不点击提审试探。保持用户指定停止点：准备提交/草稿，不提交审核/发布。用户另行明确授权才执行下一阶段；协议生成/协议审核也独立处理。

对外报告每款已做/未做、草稿状态、自检环境和限制。不得承诺审核时长或通过率；不代替用户联系审核人员。
